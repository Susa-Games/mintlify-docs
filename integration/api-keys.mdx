## Key types

| Key | Used for | Lives in |
| --- | --- | --- |
| Game key | SDK init inside the game client | Game binary / env |
| Developer API key | CI/CD build and Addressables uploads | Pipeline secrets |

Send the developer API key as `Authorization: ApiKey {key}` — not as a bearer token. It
works on the [build upload](/integration/builds#upload-via-ci-cd) endpoints and on the
[Addressables](/integration/addressables#upload-from-ci) upload and publish endpoints,
scoped to the games you own.

## Rules

**Game key goes in the client.** Never put the developer API key inside game code — it has wider permissions than the game key.

In Unity the game key lives in the `PlatformConfig` asset, created via **SusaPlay →
Setup**. `SusaPlaySDK.Initialize()` reads it from there.

```csharp
// Correct — the SDK reads the key from PlatformConfig
await SusaPlaySDK.Initialize();
```

Never hardcode the key in a script. Anything compiled into a WebGL build is readable by anyone
who opens the browser devtools, so treat the game key as public — it is scoped to a single game
and grants nothing beyond it.

**Separate production and test keys.** Keep a separate `PlatformConfig` asset per environment and
swap it at build time, so a test build can never talk to production:

```text
Assets/SusaPlay/PlatformConfig.asset          # production
Assets/SusaPlay/PlatformConfig.staging.asset  # staging
```

## Generate or rotate a key

1. Developer Portal → **API Keys**
2. Click **Generate key**. To replace an existing key, click **Regenerate API Key**, then
   **Yes, regenerate**
3. Copy the key immediately — it is shown once

You have one developer API key. Regenerating replaces it, and the old key **stops working
immediately**, so update your pipeline secrets right after you regenerate.

## If a key is exposed

1. Regenerate it in the Developer Portal — the exposed key stops working at once
2. Update the secret in every pipeline and environment that uses it
