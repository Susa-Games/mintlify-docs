## Available SDKs

| Platform | Package | Min version |
| --- | --- | --- |
| Unity (C#) | `com.susaplay.sdk` via UPM | Unity 2021.3+ |

<Note>
Unity is the only SDK today. There is no JavaScript or TypeScript package.
</Note>

Games run as WebGL builds inside the SusaPlay shell. The shell starts the SDK, supplies the
player's token, and runs checkout and ads; other calls go straight to `api.susaplay.com` with
that token. The same code works in production and in the developer preview.

## Installation

Add to `Packages/manifest.json`:

```json
{
  "dependencies": {
    "com.susaplay.sdk": "https://github.com/Susa-Games/com.susaplay.sdk.git#v1.9.1"
  }
}
```

Or in Unity Package Manager → **Add package from git URL**:

```text
https://github.com/Susa-Games/com.susaplay.sdk.git#v1.9.1
```

Then open **SusaPlay → Setup**, paste your game key, and click **Save**.

## Modules

Every module hangs off the static `SusaPlaySDK` class and is populated by `Initialize()`.

| Property | What it does |
| --- | --- |
| `SusaPlaySDK.Auth` | Current player — uid, display name, guest flag |
| `SusaPlaySDK.Purchases` | Platform wallet, store catalogue, real-money checkout |
| `SusaPlaySDK.CloudSave` | Versioned cloud save read and write |
| `SusaPlaySDK.Analytics` | Custom events |
| `SusaPlaySDK.Achievements` | Unlock achievements and track progress — [Achievements](/sdk/achievements) |
| `SusaPlaySDK.Ads` | Rewarded and interstitial ads — [Ads](/sdk/ads) |
| `SusaPlaySDK.Webhooks` | Your game's own events, forwarded to your server — [Webhooks](/sdk/webhooks) |
| `SusaPlaySDK.Backend` | Authenticated calls to SusaPlay's API — [Api and Backend](/sdk/api-and-backend) |
| `SusaPlaySDK.Api` | Calls to a partner's API when your game runs in a partner embed — [Api and Backend](/sdk/api-and-backend) |
| `SusaPlaySDK.LiveOps` | Campaign and offer content |

## Initialization

One call sets up everything. Identity is resolved by the shell during the handshake, so there
is no separate identity step.

```csharp
using susaplay.SDK;
using UnityEngine;

public class Bootstrap : MonoBehaviour
{
    private async void Start()
    {
        await SusaPlaySDK.Initialize();

        // Every module is ready from here on.
        var wallet = await SusaPlaySDK.Purchases.GetPlatformWallet();

        SusaPlaySDK.MarkGameLoaded();
    }
}
```

<Warning>
Await `Initialize()` before touching any module. The properties are null until it completes,
and a second call returns the same task. If initialization times out, `Initialize()` completes
without throwing and the modules stay null; call it again to retry.
</Warning>

If the shell does not respond within 15 seconds, initialization logs an error and gives up.
Guard against null modules if your game can run standalone.

<Tip>
In the Unity Editor, SDK 1.9.0 and later answer `Initialize()` with the Editor Simulator, so
every module is ready in Play Mode without a build. See
[Test in the Unity Editor](/sdk/editor-simulator).
</Tip>

## Version

The SDK reports its version to the shell during the handshake. Current release: **1.9.1**.

Some behaviour is version-gated — `session_start` analytics requires 1.3.0 or later, and the
Editor Simulator 1.9.0 or later. Pin a release tag (`#v1.9.1`) for reproducible installs. Rebuild
your game after upgrading the package; the version is compiled into the WebGL build.
